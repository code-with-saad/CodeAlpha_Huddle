## Decisions
- Free plans only, no credit card. Client and API are two separate Vercel projects.
- Realtime: Ably (REST publish from the API after each DB write, token auth for clients). MongoDB stays the source of truth.
- Files: Cloudinary, direct client upload with server-signed requests.
- Auth: JWT in the Authorization header (localStorage). XSS tradeoff will be documented in the README.
- Invites: by email or username create an in-app pending invite (no email is sent). A shareable, revocable link joins as Viewer by default, Member selectable. Gmail SMTP with an app password is a possible later addition, decided with the owner.
- Time-based notifications (due soon, overdue): generated lazily on load unless Vercel's free cron allows a frequent schedule. Limits to be checked in Phase 5.
- Type: IBM Plex Sans (UI) and IBM Plex Mono (dates, counts, keys). Icons: lucide-react through one `Icon` wrapper, stroke 1.5.
- Accent: petrol blue `#0B6580` (light) and `#5DB4D2` (dark). All text, accent and status pairs are at least 4.5:1 on every surface. The control border token is at least 3:1 on every surface. No blur anywhere and no card left stripe.

## Phase 5 log
- Architecture: the API stays stateless and MongoDB stays the source of truth. After every successful write the API publishes a small event over Ably REST and awaits it before answering (a failed publish is logged and never fails the request), because a Vercel function can freeze once the response is sent. Notifications and Cloudinary clean-up are awaited before the response for the same reason.
- Channels: `project:<id>` carries board events and presence; `user:<id>` carries personal events. The browser never sees the API key. `GET /api/realtime/token` returns an Ably token request for the signed-in person, with capability `subscribe`, `presence` and `history` on the channels of projects they belong to plus `subscribe` and `history` on their own user channel. Every role, viewers included, is subscribe-only; all writes go through the REST API where roles are checked. Membership and role changes publish `access.changed` to the affected person, whose tab then asks for a new token; Ably detaches channels they may no longer read.
- Events on the project channel: `card.upsert` (any card field, checklist, attachment or comment count), `card.moved` (with the final index in the column), `card.removed`, `comment.created`, `comment.updated`, `comment.deleted`, `board.reload` (columns, labels, or a list that had to be renumbered) and `project.changed` (name, archive state, members, roles). Every event carries the actor and the tab that caused it, sent by the browser in an `X-Tab-Id` header and carried to the publisher with AsyncLocalStorage. A tab ignores its own echo; other tabs, including another tab of the same person, apply it. Events are idempotent.
- Client: one Ably connection per tab, loaded on demand as its own chunk. Channels are shared and reference counted, and detached and released when the last listener leaves, to stay well under the free plan's connection and channel limits. The board applies events in place. While a card is being dragged, events are held and the board reloads after the drop has been saved. When a channel attaches without resuming (first attach or after a long outage) the screen refetches from the API instead of trusting the stream. Optimistic UI with rollback is unchanged.
- Presence: avatars of other people who have the board open, one per person even with several tabs.
- Notifications: assigned, mentioned (comments and description), comment on a card you follow, due soon, overdue, and invited. Never for your own actions; a mentioned person gets one mention, not a second comment notification. Live toast, unread badge, a bell dropdown with the latest eight, and a full page with All and Unread filters, paging and mark all read. Notifications expire after 60 days.
- Watchers: follow or unfollow a card from its panel (viewers can follow too). The creator, assignees, commenters and mentioned people follow automatically.
- Due soon and overdue without a scheduler: I checked Vercel's docs (Cron Jobs, usage and pricing). On the Hobby plan a cron job may run only once a day and not at a precise time, so a frequent cron is not possible. Instead the API creates these notifications lazily. Whenever someone's app loads, the tab becomes visible again, every five minutes while it stays open, or they open their notifications, the API looks at cards due today, tomorrow or overdue (up to 14 days) that they are assigned to or follow, and creates any that are missing. A key of person, card and due date makes it idempotent, and changing a due date creates a new one. Dates are compared in UTC.
- Bugs found in testing and fixed: Ctrl+Enter inserted a mention instead of posting when the mention list was open; after any completed drag, live events stayed on hold forever (resume was only called on cancel); and my first reconnect test simulated an outage that Ably does not treat as one (an explicit close does not reattach channels), so the tests now exercise a non-resumed re-attach and a real dropped connection separately.
- Verified against real Ably: 55 of 55 API checks (token capabilities for viewer, member, outsider and after joining or leaving, every event name and payload, notifications and their rules, watchers, list, paging, read state, lazy due notifications including idempotency and changed due dates). Earlier API suites still pass (82, 49, 68). In headless Chrome at 375, 768 and 1280 with two signed-in people: 89 of 89 checks (single connection, presence, live create, move, drag, edits and comments, mention and assignment toasts, bell, notifications page, role change reflected live, resync after a non-resumed re-attach and after a dropped connection), no console errors.
- Known gaps: a modal dialog makes toasts unclickable while the card panel is open (they dismiss on their own). "Due soon" only counts cards assigned to or followed by the person; there is no "done" state, so a card sitting in a Done column still becomes overdue (archive it, or clear the date). The presence list shows people, not which card they have open. Vercel deploy and a check against the real production origins are still pending on the owner's projects. Real phone not tested.

## Phase 6 log
- Activity log: every meaningful change writes one line (who, what, which task, when): task created, moved, renamed, archived, restored, duplicated, assigned, priority and due date changes, comments, attachments, bulk actions (one line per action), column changes, members joining, leaving and role changes, project edits and archive. Names are copied into the line, so it still reads correctly after a rename. Lines expire after six months. The Activity tab filters by kind, by person and by task title, with paging. Writes are awaited before the response, like realtime events.
- Search and filters: the Board, List and Calendar share one filter bar (text on titles, assignee including "me" and "unassigned", label, priority, due date: overdue, today, next 7 days, none). Filters live in the URL, so a filtered view can be shared or reloaded, and they carry across the three view tabs. While filters hide part of a column, dragging and Move up and down are off (the drop position would be wrong) and a note says so. `GET /api/search` searches project names, task titles and descriptions across every project you belong to; the palette uses it.
- Views: Board, List (sortable by task, status, priority and due date; tasks without a due date always sort last; rows become stacked cards on a phone) and Calendar (month grid from tablet width with a plus on each day to create a task due that day, a day by day agenda on phones). All three share one live board, so switching keeps realtime updates and the card panel. The open card is `?card=` in the URL on every view.
- Archive and restore, never a hard delete: cards, columns and projects are archived (soft). The Archive tab lists archived tasks and columns; members restore tasks, admins restore columns; a restored task returns to its old place if its column still exists, otherwise to the first column, and restoring a column brings back the tasks that were archived with it. The Projects page has an Active and Archived tab, and owners can restore projects.
- Duplicate: copies title (with "(copy)"), description, labels, assignees, priority, due date and an unticked checklist right below the original; attachments and comments are not copied.
- Bulk actions: Select on any view, then move, assign or unassign, add or remove a label, or archive up to 100 tasks in one request. Assigning several tasks to one person creates one notification, not one per task. Every action answers with what it changed.
- Undo: a toast with an Undo button (eight seconds) after archiving a task, bulk move, assign, label and archive, and deleting a column with its tasks. Bulk move undo restores the exact earlier position keys; assign and label undo apply the inverse only to the tasks that actually changed. Moving tasks into another column when deleting a column is the one action without an Undo.
- Command palette (Ctrl or Cmd + K): jump to a project, create a task (in the current project, or in one of yours from elsewhere), search tasks across all projects, go to notifications or profile, change theme, open shortcut help. Arrow keys and Enter, Escape closes, proper combobox and listbox roles. Shortcuts: `c` new task, `/` filter box (palette outside a project), `?` help. Single key shortcuts are ignored while typing or when a dialog is open.
- Bugs found in testing and fixed: typing fast in the filter box dropped characters because it was bound directly to the URL, whose updates are asynchronous (it now keeps its own text and updates the URL after a short pause); a toast can sit over the lower cards on a phone, which the test helper now closes before tapping. A false alarm worth noting: two copies after Duplicate came from running my debug script twice on the same data.
- Verified against live Atlas: 77 of 77 API checks for this phase (activity content and every filter, duplicate, restore, archive list, column restore, bulk validation, order, exact restore, notifications, search) plus all earlier suites (82, 49, 68, 55) still pass. Verified in headless Chrome at 375, 768 and 1280: 228 of 228 checks (filters and URL, all sorts, calendar grid and agenda, selection, every bulk action with Undo, duplicate, archive and restore, column delete and Undo, activity filters, palette search and navigation, all shortcuts, archived projects tab), no console errors other than Ably's own "Connection closed" message when a test browser closes.

## Phase 7 log
- What "done" means: there was no done state, so a column can now be marked as counting as done (new projects mark Done by default; any column can be switched from its menu on the Board, admins only). A task entering such a column gets a completion date; leaving it reopens the task; moving between two done columns keeps the original date. This holds for drag, the Move to menu, bulk move and its Undo, duplicate, restore from the archive, and deleting a column with a target column. Switching a column on or off completes or reopens the tasks in it. Finished tasks are no longer overdue: the card shows Done instead of a red date, the list, calendar and card panel follow, and due soon and overdue notifications skip them.
- Dashboard (`GET /api/projects/:id/dashboard`, tab next to Calendar, visible to every member including viewers): summary tiles (open, completed with the completion rate, overdue, due in 7 days, unassigned); tasks by status in board order (done columns in green); tasks per person as stacked open and done bars plus an unassigned row; open tasks by priority; a chart of tasks completed per day (columns) and created per day (line) over 7, 30 or 90 days; and lists of overdue tasks and tasks due in the next 7 days that open the card. Everything is computed from the project's real tasks. Tasks archived since are still counted in the created and completed history, but not in the totals. Days are UTC calendar days.
- Chart design follows the data visualisation rules: one accent for open work, green only for done, a neutral line for created; columns capped at 24px with a 4px rounded data end and a square baseline; a 2px line; an 8px end marker with a surface ring; hairline grid; a 2px gap between stacked segments; values at the end of bars; text in text tokens; a legend for two series; a crosshair and tooltip on hover; arrow keys step through days when the chart is focused; and "Show table" swaps the chart for a table of the same numbers. Both themes use tokens only.
- Live: the dashboard reloads itself about a second after any board, comment or project change from anyone, so a teammate finishing a task changes the numbers without a reload.
- Bugs found in testing and fixed: right after creating a project its realtime channel was refused (the person's token was issued before the project existed), so a brand new project had no live updates. The API now signals an access change to the creator, the client asks for a new token before opening the new board, and any channel refused earlier is attached again once a new token arrives (this also covers joining by link). In the screenshots the stacked bars were drawn one above the other because my class name `.stack` collided with the form layout class; it is now `.barstack`. Paragraphs in dashboard cards were forced onto one line by the list style and ran past the card on a phone.

- Public header: Home, Features (scrolls to the features), About, Contact, plus Log in and Create account, with a menu button on phones. New About and Contact pages. The contact form sends an email to `CONTACT_TO` (default `xyroxx02@gmail.com`) with the sender as the reply address, is limited to 5 messages an hour per IP, ignores bots through a hidden field, and falls back to the plain address when mail is not set up.
- Password fields have a show and hide button (login, register, change password).
- Toasts: success, info, warning and error, each with an icon as well as a colour. Added warnings for hitting a rate limit, a session that ended, and going offline (with a success message when the connection returns), and success or info messages for logging in, creating an account, logging out and creating a project.
- Board scrolling: columns now share the width of the screen (between 224 and 320 px), so four columns and the Add column button fit on a laptop without scrolling; when the board is still wider, arrow buttons appear in the gutter beside it, and the mouse wheel over empty space scrolls it sideways. Phones keep swipe and snap. Fixed on the way: the scroll helper attached before the board had loaded, so the arrows would never have appeared.
